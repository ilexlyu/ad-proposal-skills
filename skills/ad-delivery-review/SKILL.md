# 交付质检与复盘

目标：交付前发现风险，交付后沉淀资产。真正高级的提案人不是只做完一份 PPT，而是把这次项目变成下一次可调用的方法。

## Inputs

- PPT 内容、提案大纲、客户反馈、最终中标/未中标结果、过程材料。
- 若只是初稿，做交付质检；若项目已结束，做复盘沉淀。

## Delivery QA Workflow

1. **逻辑检查**
   - 主线是否清楚；章节是否有因果；每页是否只有一个主判断。
2. **证据检查**
   - 数据是否有来源；年份是否过期；结论是否超出证据。
3. **客户检查**
   - 是否回答客户最关心的问题；语气是否适合决策人。
4. **页面检查**
   - 是否重复、堆字、没有转场、标题不像结论。
5. **风险检查**
   - 哪些判断容易被客户挑战；哪些页面需要备选说法。

## Retrospective Workflow

1. 提炼本次有效判断：哪些洞察、表达、页面被接受。
2. 记录客户偏好：喜欢/不喜欢的逻辑、视觉、语言、案例类型。
3. 记录踩坑：资料不足、决策误判、表达不清、流程延误。
4. 识别可沉淀资产：资料源、提示词、页面结构、视觉规则、客户画像。
5. 建议下一步可封装成哪个 Skill 或 reference。

## Output Format

```markdown
## 交付质检清单
| 问题 | 严重程度 | 所在页/章节 | 修改建议 |

## 风险提示
- ...

## 复盘沉淀
| 类型 | 本次经验 | 下次可复用方法 |

## 可沉淀为 Skill 的资产
- ...
```

## Quality Bar

- 必须区分“这次项目经验”和“下次可复用方法”。
- 不只写总结感想；要产出可执行修改清单和可复用资产。
- 对新人解释为什么某个问题会影响客户购买，而不是只说“这里不够好”。
